# 隔离小集群升级排程计划器

给一组相互隔离的小集群排升级顺序。各集群所在**时区、禁止变更窗口、软件版本
依赖、工程师可值守时间**均不同；计划器在固定日期上确定性地给出维护窗口，
并在拖拽改动后用同一套规则重算冲突。

## 运行

零第三方依赖（Python 3.11+ 标准库 + 原生前端）：

```bash
./run.sh 8000          # 然后浏览器打开 http://localhost:8000/
# 或指定场景：
python3 -I -m ...      # 见 run.sh；隔离模式下需显式 sys.path
```

跑测试：

```bash
python3 -I tests/run_tests.py        # 45 个后端单元/端到端测试
node tests/test_frontend_logic.js   # 前端坐标/吸附/时区逻辑
```

## 核心设计

### 1. 时间与 DST：UTC 时刻 + 显式时区，固定日期可复现

- 引擎内部一律使用带时区的 **UTC `datetime`** 和 **15 分钟槽位**；本地墙钟
  （黑窗口、值守窗口、拖拽输入）只在边界经 IANA 时区转换。
- **引擎不读取系统时钟**（`tests/test_guards.py` 静态保证），同一份输入在
  任何机器、任何日期运行结果一致。
- 春季跳变的缺口（gap）：不存在的本地时间按 PEP 495 `fold=0` 解释，其 UTC
  回转后恰好落在跳变后第一个有效墙钟，排程不会落入真空时段。
- 秋季回退的重复小时（fold）：区间左端点取 `fold=0`（第一次出现）、右端点取
  `fold=1`（第二次出现），半开区间完整包住重复的那一小时——回退夜的值守窗
  在 UTC 轴上自然变成 25 小时。
- 跨午夜窗口（如东京 22:00–04:00）按本地墙钟解释，UTC 跨度恒定。
- 规划区间内每个时区的 DST 切换点由 `find_dst_transitions` 枚举，页面上以
  紫色竖线标记，侧栏列出 UTC 时刻、类型与偏移变化。

### 2. 冲突规则（自动排程与拖拽重算共用同一套纯函数）

| 类型 | 含义 | 严重度 |
| --- | --- | --- |
| `horizon` | 窗口超出规划区间 | 错误 |
| `blackout` | 与禁止变更窗口重叠 | 错误 |
| `engineer_off` | 工程师不在可值守时间 | 错误 |
| `engineer_busy` | 同一工程师同时值守两个窗口 | 错误 |
| `dependency` | 前置集群未升级完就开始 | 错误 |
| `version` | 目标版本低于前置集群目标版本 | 错误 |
| `rollback_pool` | **共用回退人手的集群同时卡在关键步，超出池容量** | 错误 |
| `pinned_moved` | 固定维护窗口被手动移动 | 警告 |

### 3. 回退人手争用——本工具显式处理的核心冲突

回退人手建模为**容量池**（`rollback_pools`），每个集群归属一个池；步骤标注
`critical: true` 表示该阶段一旦失败需要回退人手兜底。

- 同一时段内尽量并行：没有共享资源的集群排在同一槽，缩短端到端周期；
  非关键阶段（预检/收尾）的重叠不消耗回退容量。
- 但同池集群的**关键步**在时间轴上同时活跃数不得超过池容量。扫描线在每个
  关键段事件点统计活跃集合，超限时对每个涉事集群生成 `rollback_pool` 冲突，
  明确写出“须将其中至少 N 个延后到关键步结束之后”。
- 自动排程把回退池容量当硬约束逐槽扫描，天然产出关键步首尾相接的错峰方案；
  手动拖拽制造争用时，重算会把冲突显式报出并把窗口标红。

### 4. 排程策略

确定性贪心列表调度：固定窗口集群先占位 → 其余按版本依赖拓扑序 → 每个集群从
最早可行槽（规划起点、前置结束时间、槽对齐）起逐 15 分钟扫描，取第一个满足
全部硬约束的槽。无可行窗口则列入 `unscheduled` 并附原因，绝不静默挪动。

## 页面交互

- 甘特行：绿色底纹为工程师值守窗，紫色斜纹为禁止变更窗，蓝色块为维护窗口
  （橙色分段即关键步），紫线为 DST 切换点。
- **按住维护窗口拖动** → 15 分钟吸附、换算回 UTC → 调 `/api/recheck` 全量
  重算 → 冲突着色、侧栏告警、周期统计即时更新。
- “重新自动排程”清除手动改动；“导入场景 JSON”可加载自定义样例。


## 样例场景覆盖的固定日期事实

- 纽约 `America/New_York`：2026-11-01 06:00 UTC 秋季回退，黑窗口刻意覆盖
  重复小时；
- 悉尼 `Australia/Sydney`：2026-10-03 16:00 UTC 春季跳变（南半球）；
- 伦敦/柏林：2026-10-25 01:00 UTC 秋季回退；
- 东京 `Asia/Tokyo`：无 DST，黑窗口与值守窗跨午夜；
- 纽约→东京版本依赖，且两者共用容量 1 的回退池；法兰克福为固定窗口集群。
